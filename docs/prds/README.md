# Product requirements documents

Store PRDs here using descriptive, lower-case hyphenated filenames, such as `tarot-reading.md`.

A PRD describes the problem, intended users, scope, expected behaviour and acceptance criteria. Include its date and status (draft, approved or superseded), and link relevant research. A draft does not authorise implementation; record approved scope changes in [decisions](../decisions.md).
